# Release Notes – v1.15.2

## What is new in v1.15.2

Two new features – a **Web view** next to the map and **group watching** in the
Watchlist – plus fixes that make **KISS/TCP usable with a single node** and
stop the MH list, map and chat tabs from appearing empty after adding the
first node profile.

---

## 🌐 Web view

A new **🌐 Web** tab right next to the map embeds any number of web pages
(e.g. `https://meshmap.oevsv.at/`, `https://meshcom.oevsv.at/`) in a sandboxed
iframe, with a page selector, an "Open in new tab" button and a remembered last
selection. Manage the pages under **Settings → 🌐 Web** (name, URL, enabled;
http/https only, invalid URLs are rejected on save; "Insert examples" adds the
two OE pages). The tab is shown only while at least one enabled page exists.
Pages that forbid embedding (`X-Frame-Options` / CSP `frame-ancestors`) stay
blank – use "Open in new tab" for those.

---

## 👥 Watchlist: groups

The Watchlist can now also follow **groups**, e.g. a quiet group like `26261`
(Hessen). Add group numbers (one per line, with or without `#`) under
**Settings → 📻 Watchlist → Group List**. Every new text message in such a
group raises a toast (sender + group), the alert tone and – if voice is
enabled – an announcement, in all five languages. It works independently of the
group filter and of whether the group tab is open. Own messages (any SSID of
your own callsigns/nodes) are ignored, and the voice announcement is throttled
to once per 5 minutes per group.

---

## 📡 KISS/TCP for a single node

KISS/TCP can now be enabled directly under **Settings → Connection** – toggle,
connection status and the node password for `--kiss auth on` – so a single node
no longer has to be configured as an "additional node" first. The primary node
profile is created automatically; if its own password is empty, the global
console password is used for KISS authentication. The node bar above the chat
(and the node selector on the NET Console page) now only appears when **more
than one** node is enabled.

---

## 🔧 Bug fixes

- **MH list, map and chat tabs empty after adding the first node** – adding a
  node profile moved the app from the legacy single-node state to a new
  per-node state, and the old data was only carried over if it contained
  tabs/messages and the new state was still untouched. The MH list/map (and
  sometimes the tabs) therefore appeared empty; deleting the node made them
  reappear. The carry-over now always runs, merges without duplicates and also
  recovers data of deleted/re-created node profiles when at most one node is
  configured. Nothing was lost – it just was not shown.

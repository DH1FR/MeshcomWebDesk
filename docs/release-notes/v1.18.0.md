# Release Notes – v1.18.0

## What is new in v1.18.0

**Get the node connection right: a connection check, a setup wizard with node search, and node setup over the net console.**

---

## 🔍 Connection check

- *Settings → Connection → Check settings* checks the current (even unsaved) values and explains what does not fit and what to change.
- Typical mistakes are found: the node's IP as *Listen IP* instead of `0.0.0.0`, the real UDP bind error, ping, port conflicts, nodes that share an IP or callsign, KISS reachability and the **Bluetooth hub** (running? port conflict?).
- **Callsign and SSID** are compared with what the node reports: over the net console, from the echo of a sent message and from its own packets. A new **Callsign?** badge in the status bar appears on a mismatch; a click on a red/yellow UDP or KISS badge opens the check.
- Packets that arrive but are not counted yet are explained instead of guessed (the node first reports a relay echo, then the real packet).

---

## 🧙 Setup wizard

- Five steps for a WiFi/LAN node or a Bluetooth hub (on this PC or another machine), also per additional node.
- Choose **automatic or manual** configuration once; the automatic branch checks the net console and, if it is off, guides you to switch it on in the node's web interface.
- **Node search in the local network** – hostname/mDNS, packets already received and a scan for the node's web page; the IP is picked from a **selection list**.
- Values reach the form only on *Apply to form* – you still save.
- At startup, if no node is set up and no data arrives, WebDesk asks whether to start the wizard.

---

## 🔧 Read and correct the node over the net console

- The check reads the node (`--info`, read-only) and compares ext UDP, target IP, the node's IP, KISS switches, `--nopmother` and the callsign with the WebDesk configuration.
- A button at the end of each finding corrects it on the node – **only after your click and confirmation**. Only `--extudpip`, `--extudp on`, `--kiss on|tx on|meta on` and `--setcall` can be sent. The target IP always goes first (the firmware refuses `--extudp on` otherwise), and the node's reply is shown.
- The callsign can be taken over into WebDesk or set on the node (`--setcall`, with a warning that the node's identity changes).
- A **KISS** button next to the KISS/TCP toggle switches KISS, TX and RxMeta on at the node.

---

## 🔧 Bug Fixes

- A failed UDP bind was only in the log; the red badge now shows the reason.
- Net console reads no longer send `--volt` / `--netconsole` (unknown to the Bluetooth hub).
- An empty `...EXT IP` in `--info` is no longer read as an address.
- Cancelled JS calls (reload, navigation) no longer end as unhandled exceptions.

---

## 📶 Bluetooth hub

- Recognised by the check and the wizard. The hub's `--info` now also reports callsign, ext UDP and node values in the firmware's wording (update in the hub repository; restart the hub). With it the check also compares the hub's **UDP port** and the **port it sends to** with the WebDesk settings and checks that WebDesk listens on the address the hub sends to.

---

## 📱 QR code for phone and tablet

- A **📱 button** in the navigation bar (only on wide screens) shows a QR code on request, so a phone or tablet in the same network can open WebDesk.
- **https addresses come first.** Shown are the LAN addresses of this PC with the ports WebDesk listens on; an address entered in *Settings → Access from other devices* (needed with Docker or a reverse proxy) is offered first.
- The dialog notes that over http the browser cannot "install as app" or use the location, gives the Windows firewall rule, and warns that **WebDesk has no access protection**.
- The QR library is *qrcode-generator* (MIT), shipped in `wwwroot/lib/qrcode`.

---

## 🌍 Languages

- All new texts are available in German, English, Spanish, French and Italian; the node-connection guides are updated.

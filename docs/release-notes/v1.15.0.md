# Release Notes – v1.15.0

## What is new in v1.15.0

This release adds a second, optional way for WebDesk to receive from and send to
a MeshCom node: the node's **KISS/TCP** interface. It is an **add-on on top of
ext-udp**, not a replacement – ext-udp stays the always-on base and KISS is
enabled per node with a checkbox.

---

## 📡 KISS/TCP as a per-node add-on

In **Settings → per node**, tick **KISS/TCP** to *additionally* open a KISS/TCP
connection to the node (port 8001, ESP32 firmware **v1.4+**). ext-udp keeps
running; the KISS frames are fed into the same chat / monitor / MH / map /
database pipeline.

What KISS shows that ext-udp does not:

- the **full APRS position comment** (`/B= /A= /N /P= /H= /T= /R=`), not just lat/lon/alt
- the **digipeater path** the frame travelled
- the **`/R=` relay-node list** and **`/N` neighbour count** as their own badges
- **RSSI / SNR per frame** (with `--kiss meta on` on the node)

**Sending** works over KISS too: every send gets a per-send delivery result from
the node's `0xF0` frame – *accepted* (with the assigned `msg_id`) or *rejected*
with the reason (wrong callsign, TX off, bad frame, rate limit).

**Authentication** is optional: with `--kiss auth on` on the node, WebDesk does
the same HMAC-SHA256 challenge/response as the NET Console, using the per-node
password.

### KISS and ext-udp are complementary

KISS does **not** carry everything ext-udp does. The node's **own** position, the
**structured telemetry** panel (temp/hum/pressure as numbers) and its
**firmware/hardware** identification only come over ext-udp – the firmware never
sends its own beacons or telemetry-only frames over KISS. For a KISS-primary node
the status bar therefore shows **two** indicators, **KISS** and **ext-udp**, and
the ext-udp dot turns yellow (with a hint) when the node's own data stops
arriving. Keep `--extudp on` on the node.

## 🔀 KISS hub

A MeshCom node accepts exactly **one** KISS/TCP connection. WebDesk can now hold
that one connection and **re-serve it as its own KISS/TCP listener**, so
**Dire Wolf, YAAC, APRSdroid** and other KISS clients connect through WebDesk
instead of fighting over the node.

Configure it under **Settings → 🔀 KISS Hub**: listener port, target node
(default: the primary node) and whether it is reachable from *this PC only* or
the *whole LAN*. Received RF frames fan out to every connected client; a client's
transmit is injected via the node and the `0xF0` result is routed back to that
client. Only `type 0x00` data frames are relayed – RxMeta and TX-result stay
WebDesk-internal.

> ⚠️ The hub has no authentication of its own – only enable LAN access on a
> trusted network. Downstream apps must use your callsign (any SSID) or the node
> rejects their transmits.

---

## 🆔 Two-digit SSIDs over KISS

AX.25 addresses hold only a 4-bit SSID, so a MeshCom origin callsign with an SSID
of `-16`…`-99` is clamped to `-15` on the wire. The firmware now sends the real
callsign in a separate **SrcInfo** frame; WebDesk uses it as the true sender for
the monitor **and as the reply addressee**, so a reply to a two-digit-SSID
station is addressed to the right station instead of a non-existent `-15`.

---

## 🔑 Per-node password

The node password is now stored **per node** and is used both for the NET Console
(HMAC) and – with `--kiss auth on` – for KISS authentication. The old, unused
"TLS certificate fingerprint" field has been removed.

New in the **Console Command Helper** (Network group): `--kiss`, `--kiss tx`,
`--kiss meta`.

---

## 🔧 Bug fixes

- **Bare `ackNNN` / `rejNNN` acknowledgements** are now recognised (previously
  only the `CALL:ackNNN` inline form), so the delivery checkmark is set for ACKs
  from standard APRS clients such as PinPoint.
- **MeshCom time-sync broadcasts** (`{CET}2026-…`) are kept out of the chat over
  KISS – monitor only, matching the ext-udp behaviour.
- A **hub client's ACK** is no longer misattributed to WebDesk's own outgoing
  chat messages that share a base callsign.
- KISS info fields are decoded as **UTF-8 with a Latin-1 fallback** (Dire Wolf /
  PinPoint send CP1252).
- A **KISS connect timeout** now shows as a clean "node unreachable" status
  instead of a raw stack trace.
- **KISS auth detection** no longer stalls on a quiet node that has no
  authentication configured.

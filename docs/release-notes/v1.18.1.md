# Release Notes – v1.18.1

## What is new in v1.18.1

**Calmer chat and monitor, better on phones, and the bot only listens to `>`.**

---

## 💬 Chat

- **Reading-friendly scrolling** – the list follows new messages only while you are at the end. Scroll up to read and the position stays put; a **↓ N New Messages** button shows how many arrived meanwhile and jumps back to the end (switching tabs and sending your own message still scroll to the end).
- **Lighter updates** – chat rows are keyed, so with a full tab (500 messages) a new message no longer rewrites every row (about 8000 DOM changes for 4 messages before, about 150 now).
- **Identical messages are no longer swallowed** – a message that carries an id is identified by the id alone. Before, a second `>ping`, `73` or `ok` to the same station within 30 minutes was dropped as a "duplicate" even with a different id.

---

## 📡 Monitor

- **Show/hide on every screen size** – the ▼/▲ button in the monitor title bar, until now only on phones and small displays, works everywhere. With the monitor hidden only the title bar stays and the chat uses the freed height. The monitor is **visible by default** again.
- **No more jumping** – the saved monitor height and visibility are applied before the first paint; changing pages (e.g. MH ↔ Chat) no longer moves the monitor and the message input.
- **Faster page changes** – only the newest 200 rows are built; **Show older entries** adds 200 more, the live filter still searches all entries. With a full monitor the page build takes about half the time.

---

## 📱 Phones and touch screens

- **One-row tab bar** – up to 600 px width the tabs sit in one swipeable row instead of wrapping onto several rows (15 open tabs: about 33 px instead of about 260 px). The active tab scrolls into view, the search buttons and **+** stay in reach, and reordering by long press works as before.
- **No unwanted zoom on the iPhone** – iOS Safari zoomed into text fields with a font below 16 px and stayed zoomed. Text fields now use at least 16 px on touch devices and double-tap zoom is off; pinch zoom still works.
- **Easier to grab divider** – the divider between chat and monitor has an enlarged touch area of about 20 px.

---

## 🤖 Bot

- **Commands only with `>`** – the bot reacts only to direct messages that start with `>` and a letter (`>ping`, `>version`, `>help`, `>time`, …). `--…` belongs to the node firmware's own console commands, so `--ping`, `--version`, the em dash form and a bare `ping` are ordinary chat text and are **no longer answered** (this also applies to other apps and older WebDesk versions that still send them). With the bot switched off (default) `>ping`, `>rx`, `>version` and `>help` are still answered. WebDesk's own ping and its round-trip time use `>ping`.
- **New `>rx`** – ask a neighbour station running WebDesk how it receives you: *direct* or *via RELAY-12 (1 hop)* together with RSSI/SNR. The answer says whose signal the values are (always the last radio hop); packets that came via the gateway/server have no radio value.
- **`>ping` route** lists and counts only the relay stations (the sender is no hop), the same way as `>rx` and the MH list.
- **Decimal separator by language** – SNR and weather values in bot replies use a decimal comma (de/es/fr/it) or a point (en) according to the configured language, not the server's operating-system setting.

---

## 🔧 Bug Fixes

- The first-start setup prompt no longer asks although a node (a saved single-node connection with your own callsign) is already set up; it only appears for the placeholder callsigns (`NOCALL…`, `DH1FR-2`) and not at all once messages from the node exist.
- The chat no longer jumps to the end on every new message while you are reading older ones.

---

## 📚 Docs

- The README and the node connection guides (de/en/es/it) point to the [MeshCom UDP Bluetooth Hub](https://github.com/DH1FR/MeshComUDPBluetoothHub) for nodes without WiFi (e.g. Heltec T114).
- The README feature sections describe the current scrolling, the monitor, the tab bar on phones, the bot commands and the deduplication (message id first, 30 minutes).
- Firmware: the source of MeshCom **v4.40a.11.22** was checked against WebDesk – nothing had to change (RM1 remote-management frames are not interpreted).
